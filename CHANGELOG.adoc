== 0.5.1 (29 avril 2026)

=== Modifié

* **Repo GitHub renommé** `aloli-crystal/crystal-api-scaleway` →
  `aloli-crystal/api-scaleway` (convention de nommage Aloli : les
  créations originales abandonnent le préfixe `crystal-`). Les anciens
  liens redirigent automatiquement.
* Champ `name:` du `shard.yml` mis à jour de `scaleway-api` à
  `api-scaleway` (alignement avec le nom du repo). Le module reste
  `ScalewayApi` (sémantiquement plus naturel).
* Nouveau fichier d'entrée shim `src/api-scaleway.cr` (charge
  `src/scaleway_api.cr`) ; `require "scaleway-api"` devient
  `require "api-scaleway"`.

== 0.5.0 (25 avril 2026)

=== Ajouté

* `client.projects` (`ScalewayApi::Endpoints::Projects`) :
  - `list(organization_id:)` — `GET /account/v3/projects?organization_id=<UUID>`
    (filtre obligatoire côté API : sans lui, la réponse est `null`,
    constaté terrain).
  - `get(project_id)` — détail d'un projet.
  - `Project#default?` — vrai quand `id == organization_id`, ce qui
    signale le projet `default` créé automatiquement à l'inscription.
* Permet l'auto-découverte du `SCW_DEFAULT_PROJECT_ID` à partir du
  `secret_key` + `organization_id`, sans demander à l'opérateur
  d'aller fouiller la console.

== 0.4.2 (25 avril 2026)

=== Ajouté

* `client.baremetal.servers.update_ip(server_id, ip_id, reverse, zone)` :
  pose le reverse DNS sur une IP spécifique d'un serveur Elastic
  Metal (`PATCH /baremetal/v1/zones/{zone}/servers/{server_id}/ips/{ip_id}`).
  Complète `update(reverse:)` qui, lui, ne gère que l'IP primaire
  (IPv4). Nécessaire pour poser le reverse IPv6 automatiquement
  sans passer par la console Scaleway.

== 0.4.1 (24 avril 2026)

=== Corrigé

* Documentation de `BootType::Rescue` : le commentaire précédent
  affirmait que « les clés SSH présentes dans l'install initial
  sont automatiquement ré-injectées par Scaleway dans le rescue »,
  ce qui était une interprétation non vérifiée contre la doc
  officielle. Correction avec citation et lien vers
  https://www.scaleway.com/en/docs/bare-metal/elastic-metal/how-to/use-rescue-mode/[la
  how-to officielle] :
+
** L'utilisateur du rescue est `rescue` (pas `root`).
** La liste de clés est celle posée à l'install initial
   (`install.ssh_key_ids`). Aucun endpoint documenté ne rafraîchit
   cette liste sans refaire un `install`.
** Ajouter une clé au projet après création du serveur ne propage
   pas la clé dans le rescue. Pour resynchroniser, appeler
   `Servers#install` avec la liste à jour (destructif au disque).

Aucun changement de code — uniquement de la doc qui était
trompeuse.

== 0.4.0 (24 avril 2026)

=== Ajouté

* `client.baremetal.servers.find_any_zone(server_id)` : balaye
  `ScalewayApi::ZONES` à la recherche d'un UUID dont on ne connaît
  pas la zone. Retourne le premier `Server` trouvé (l'UUID est unique
  côté Scaleway) ou `nil`. Les zones qui répondent 501
  `unknown_service` (pas encore activées pour Elastic Metal) sont
  silencieusement ignorées, les autres `ApiError` sont relayées.
  Utile pour les outils qui importent un serveur par UUID sans
  savoir dans quelle région Scaleway il vit.

== 0.2.0 (20 avril 2026)

=== Ajouté

* `client.baremetal.servers.reboot(zone, server_id, boot_type: BootType::Rescue)` :
  redémarre un Elastic Metal avec choix du mode boot (`normal` ou `rescue`).
  Les clés SSH posées à la création sont ré-injectées automatiquement par
  Scaleway dans le rescue, pas besoin de refaire quoi que ce soit côté
  compte. Rescue par défaut : ~1 h avant bascule auto en normal.
* Enum `ScalewayApi::Endpoints::Baremetal::BootType` : `Normal` | `Rescue`.

== 0.1.0 (20 avril 2026)

=== Ajouté

==== Fondations du projet

* Squelette initial (`shard.yml`, `LICENSE` MIT, README bilingue FR/EN).
* Convention Aloli : branche par défaut `production`, messages de commit
  en français, licence MIT, auteurs `ALOLI sas`.

==== Cœur du client

* `ScalewayApi::Client` : authentification par en-tête `X-Auth-Token`,
  sans signature ni synchronisation d'horloge (API Scaleway bien plus
  simple que celle d'OVH de ce côté-là).
* Routage par zone : `default_zone` fixé à `fr-par-2`, surchargeable par
  client ou par appel. La zone fait partie du chemin
  (`/baremetal/v1/zones/{zone}/...`), pas du hostname.
* `default_project_id` optionnel à la construction, indispensable pour
  les créations de ressources.
* Transport HTTP abstrait `ScalewayApi::HttpTransport` avec
  implémentation `DefaultHttpTransport` (stdlib `HTTP::Client`), permet
  l'injection d'un double en test.

==== Endpoints de provisioning

* *SSH keys IAM* (`/iam/v1alpha1/ssh-keys`) : `list`, `get`, `create`,
  `delete` — toutes portées par un `project_id`.
* *Elastic Metal offers* (`/baremetal/v1/zones/{zone}/offers`) : `list`,
  `get`. Exposition brute du payload Scaleway via `Offer#raw` pour les
  détails matériels et tarifaires.
* *Elastic Metal OSes* (`/baremetal/v1/zones/{zone}/os`) : `list`, `get`,
  `find_by_name_prefix` (helper pour résoudre `"debian"` → `os_id`).
* *Elastic Metal servers* (`/baremetal/v1/zones/{zone}/servers`) :
  `list`, `get`, `create` (création + installation couplées), `install`
  (réinstallation d'un serveur existant), `update` (notamment le reverse
  DNS), `delete`, `events` (suivi d'installation).
* `Install` : struct avec `os_id`, `hostname`, `ssh_key_ids` +
  `user`/`password`/`service_user`/`service_password` optionnels.
  Sérialisation qui omet les champs nil (Scaleway refuse `null`).
* DNS inverse via le champ `reverse` de `servers.create` et
  `servers.update` (Scaleway n'a pas d'endpoint dédié comme OVH).

==== Taxonomie d'erreurs

* `ScalewayApi::Error` (base).
* `AuthenticationError` (HTTP 401/403).
* `NotFound` (HTTP 404).
* `RateLimited` (HTTP 429, expose `retry_after`).
* `ApiError` (autres, expose `http_status` et `error_code` —
  correspond au champ `type` de la réponse d'erreur Scaleway, ex.
  `"invalid_argument"`, `"quotas_exceeded"`, `"permissions_denied"`).

==== Tests et exemples

* Specs Crystal avec `FakeTransport` pur stdlib (aucun appel réseau) :
  en-têtes, query strings, corps JSON, gestion d'erreurs, sérialisation
  des `Server`, `Event`, `Install`, `SshKey`, `Offer`, `Os`.
* Exemple exécutable
  `examples/provision_debian_baremetal.cr` : création + installation
  Debian + polling événements + lecture des IPs, avec garde-fou
  `SCW_CONFIRM=yes`.

==== Intégration continue

* CI GitHub Actions : format Crystal + specs sur Linux et FreeBSD 15
  via `cross-platform-actions/action`, avec compilation de l'exemple
  (`mkdir -p bin && crystal build ...`).
